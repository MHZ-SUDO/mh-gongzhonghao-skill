# 技术讲解视频：去重、精剪、合并与字幕

用于录屏、手写板书和口述推导的剪辑。与 [project-format.md](project-format.md) 配合使用：源文件、剪辑区间、词时间戳、更正和交付信息按该文件的字段保存。不要直接套用某一期的文件名、切点、阈值或算例参数。

## 1. 建立素材身份和内容顺序

1. 先运行本包 `scripts/media_tools.py` 的 `inventory` 子命令，检查文件大小、SHA-256、视频/音频流、时长、画幅、帧率和旋转信息。具体参数先看该子命令 `--help`。
2. 只把字节哈希相同的文件标为“完全重复”。相同画面、同名带“(1)”、相近时长、相同转写都只能提示相似。重编码版可能内容相同但哈希不同，应比较对应画面和音轨，保留质量更好的版本，按当前任务的授权处理副本。
3. 用户要求去重时，每一组至少保留一份完整原片；删前重新验证“拟保留文件存在且哈希与副本相同”。优先回收站，并记录原路径、保留路径、哈希、实际操作结果。重命名后再核验保留文件。避免把失败的回收动作记为成功。
4. 顺序依据内容衔接：各段开头和结尾、板书状态、未完成句、同一算例的状态量及后续引入。时间戳文件名只作为线索。检查所有段，而不是默认永远恰好两段。
5. 先建立“讲解内容地图”：本期问题 → 必需背景 → 推导 → 数值例 → 误差或适用条件 → 总结。记录每项的原片区间和画面证据。后面删减时以这条讲解链检查完整性。

保留原片和输入文档。除用户指定的整理操作外，把缓存、代理、转写、渲染和交付写入本期独立目录。新一期使用新目录，避免覆盖上期。

## 2. 转写与可疑语音检查

优先复用当前电脑完整可用的离线模型和已验证缓存。重新探测 Python、FFmpeg 和模型路径；历史绝对路径是线索。CPU 可先试 `faster-whisper` 的 `medium`、`int8`，GPU 和模型大小依据实际条件选择，不为每个项目重复下载。

保存以下信息：源文件哈希、模型身份、语言、解码配置、提示词、完整段和词时间戳、完成标记。中断时原子保存检查点；续跑需验证源文件和配置身份，处理重叠窗口，防止重复句。模型未完成、遗漏尾部或缓存对应别的文件时，不得据其生成完整成片。

`initial_prompt` 仅放本期术语、变量读法等短词表，例如“显式欧拉、步长、航向角、阻力矩”。长指令、完整预期台词和“请逐字记录……”容易进入转写。低音量书写、开头和长静音处尤其需要检查。

按以下证据标出可疑片段，并回听原声、对照板书：

- 词时长为零或大量词挤在同一时间点；字幕文字量明显不可能在该时长内说完。
- 出现订阅、点赞等与原片无关的套话，或提示词被反复朗读。
- 长静音处仍有密集转写；段落重复、前后矛盾，或末尾文字超过实际音频。
- “0.01”“0.1”“1.0”、角度/弧度、力/速度等数值与单位混淆。
- `k`、`k+1`、希腊字母、上下标、分数、乘号和函数名被识别成中文词。

可疑位置用短窗、去掉提示词的对照转写辅助定位。短窗 ASR 仍可能误识别，不能单凭第二次识别改数值，也不能把两次模型一致当作数学证明。检查原声、板书和独立计算后再更正。保留原始转写，另存校对层。

VAD 可帮助定位候选语音，但先用本片低声讲解和停顿样本验证；避免把低声读公式删掉。静音检测、波形和视觉变化分别保留，后续综合判断。

## 3. 决定保留、删除和加速

用户说“尽量短”时，按以下顺序压缩：静止等待 → 重复起句/重说 → 无意义口头语 → 重复复习 → 无解说书写。推导中的假设、定义、关键变形、正确算例及结论至少保留一套完整讲解。独立算例即使使用相同变量，也不自动视为重复内容。

| 素材情况 | 优先处理 | 复核要点 |
|---|---|---|
| 静音、画面基本不变、无阅读必要 | 缩短等待 | 保留必要呼吸和阅读停顿；检查鼠标选择等操作是否有含义 |
| 无解说，正在书写或画图 | 保留或适度加速 | 可从 2 倍速试起；完成后给阅读时间；关键构造过程仍应能看懂 |
| 正常讲解或低声读公式 | 基础精剪阶段保持原速 | 不因音量低而删；基础成片完成后统一1.25倍，音频保音高 |
| 独立“嗯、呃”等 | 可删候选 | 原声确定无语义，切口不伤前后词；连续短切过多时保留自然节奏 |
| “然后、所以、那么、也就是说”等 | 按语义判断 | 它们可能承担递进、结论和转场，不做全局词表删除 |
| 重说且最后一次完整正确 | 优先保留正确完整的一次 | 删除错误引入后，代词、板书和“刚才”等指代仍成立 |
| 数值或单位纠正 | 按第 5 节处理 | 不能只留下错误板书或删除后面的正确解释 |

先在数个代表片段校准静音阈值、最短等待时长和视觉变化阈值。一个项目中可工作的固定 dB 值不代表另一个麦克风也适用。画面变化可能来自光标、缩放、滚动和压缩噪声；结合实际帧判断书写。

自动候选区间必须减去非口头语的词级保护区。词边界前后保留自然余量，可先试约 0.1–0.2 秒，再按原声调整；ASR 边界不精确时扩大保护。手工切点也要检查是否穿过词、数字、单位或公式朗读。一个删除片段中间包含被保护词时，应分段或放弃删除。

逐个回听语义删段和所有合并接缝，连同剪口前后几秒的实际成片。对“去掉复习”“去掉错误重算”这类长删段，检查被删部分是否包含后文唯一的定义或参数。边界两侧单独听着完整，不代表拼起来连贯。

## 4. 统一时间轴、字幕和渲染

使用 `media_tools.py compile` 将按项目格式确定的编辑决策编译成统一时间轴；使用 `map-words` 生成重映射词。命令参数、支持的处理速度和输出字段以本包 CLI 及 [project-format.md](project-format.md) 为准。它们处理确定性的时间与结构，不替代内容剪辑判断或最终渲染。

### 唯一时间来源

- 每个原片用稳定的 `source_id`，记录源文件哈希。切点用同一种、明确说明的时间基准。
- 先确定输出帧率及是否需要把可变帧率源规整成稳定时间基准。规整后保存 PTS/帧映射，避免把原片秒数当作任意帧索引。
- 核对音频和视频的起始 PTS/延迟；定义源时间零点及提取时是否保留前导空隙，避免分别把各流首帧/首样本当作同一个零点。
- 统一使用半开区间 `[start, end)`；删除、保留和加速的边界有明确取整约定。记录最终使用的起止帧，而不只保存手工输入的小数秒。
- 音频、字幕、更正标注、封面长度和统计全部从编译后的时间轴计算。渲染选择帧的方式必须与时间轴声明一致。

上述编译是基础精剪层。完成基础视频、烧录字幕和封面后，再按 [final-speed.md](final-speed.md) 应用一次全片5/4映射，所有画面和时间码同步乘4/5；保留两层映射，不拿基础时间线直接验收最终倍速片。
- 如果某段加速通过抽帧实现，实际输出帧数取决于抽样相位和边界；以实际输出帧数累计时长。不要另用理想秒数累计另一套时钟。
- 为每段保留源区间、处理速度、原因、输出起点及帧数。删除区间仍进清单，但输出时长为零。

例如，一个保留行的理想映射为 `t_out = output_start + (t_source − source_start) / speed`；实际结果还须裁到该行编译后的输出范围。修改剪辑后统一重编译，不能单独给后半段字幕手动加一个估算偏移。

### 字幕重映射与校对

1. 原转写只定位，字幕文本使用独立校对层，按术语、板书和算例校正。文本替换不能冒充原片音频已经说对。
2. 使用保留词的时间范围重建句子。跨删除区间的字幕先拆分；检查是否产生“后”“速”等断词残留。不能用删除中间字符的方法拼出讲者没有表达的新结论。
3. 技术词替换可通过字符对齐分配时间，但数字、长短差异大的整句重写和公式朗读要手工复核。不要把一段时长全部均分就认定同步准确。
4. 按语义和阅读速度分行。大屏录屏可试每行约 18–25 个汉字、最多两行，再按字号与画幅调整。避免过短闪现、超长一屏、行间重叠及连续 cue 负间隔。
5. 独立 SRT 与烧录用的 ASS/字幕素材从同一最终字幕对象生成；检查 cue 数、文本、开始和结束时刻一致，考虑 SRT 毫秒、ASS 厘秒的量化误差。
6. 封面插入后全部正文字幕带统一偏移，最后一条不超过成片。重新剪辑或增加片头后，重建 SRT 和烧录字幕。
7. 数学更正可用单独的标注轨；更正应覆盖相关板书可见区间，不能只在某条字幕的中点恰好落入区间时显示。SRT 中的更正说明与画面一致；独立算例结束后及时撤下标注。

### 画面与编码

优先保持原片画幅与公式完整。需要字幕底栏时等比缩小板书后补画布，检查画面边缘、工具栏和手写公式是否被遮挡；不要拉伸填满。用户指定的 16:10、3200×2000 等只属于该项目配置。放大导出不能创造原片没有的细节。

录屏推导通常直接切换更清楚；公式画面之间的长叠化会叠成难读的双影。加速书写到完成板书后保留短暂停留。检查片头封面、所有素材接缝和片尾最后一帧，避免黑帧、重复帧和意外闪现原始桌面。

FFmpeg 可承担确定性的导出；已有剪辑软件也可使用，但导出的时间轴/项目须与删剪清单一致。不同分段先统一尺寸、帧率、像素格式、色彩标记及编码参数；确认兼容后再 concat。最终保留可播放的 MP4，通常使用 H.264/AAC、兼容像素格式和 faststart；具体码率/CRF 根据公式清晰度与文件大小检查决定。

## 5. 算例错误、笔误与下游影响

按完整内容地图逐段审核讲者说的内容和画面上写的内容：对照原声、转写、板书、变量定义、公式变形、方向、单位、数值与上下文，独立复算例题并追踪后续引用。自动转写与抽帧只辅助定位，不等于逐段实际听看；无法完成某种检查时如实说明覆盖范围，不能称已完整审核。用户已明确接受某次替代检查时，只对该次按其选择处理。

建立问题与更正台账，至少记录：原片及终版时间、原话或原式、对应板书、疑点/错误、依据和独立复算、建议正确关系、受影响的后续结论、拟处理方式、相关画面与字幕位置。

发现讲述、板书或计算中的技术疑点及错误时，在最终定稿和发表前，用可用的问答弹窗向用户清楚展示问题位置、原内容、依据和建议，询问是否按建议更正；多个问题可在一次弹窗中分项展示，必要时附对应画面。等待用户明确选择，期间继续不依赖选择的工作。不要把未答复当同意，也不要擅自把有争议的讲法改成既定事实。用户明确选择不改时保留原内容并记录；纯ASR错字且原声、板书本来正确，可以直接校对，不需逐字询问。

用户同意更正后，在原讲解或错误板书出现的画面旁放清楚、就近、不遮挡原式的更正标注，覆盖相关讲述和板书可见时段；同时在对应烧录字幕和独立SRT中写明勘误，而非把讲错的原声伪装成已说对。必要时采用经授权的补录；按统一时间映射核查标注、字幕和Word/教学图一致。仅修改Word、只改SRT或只在视频其他位置提示，不算完成视频本处勘误。

按以下顺序判断：

1. **ASR 错误**：原声和板书本来一致，修正转写/字幕即可。
2. **讲者已自我纠正的口误或笔误**：优先保留正确重述及必要解释，删除错误片段后的衔接须重新回听；仅删除已被正确重述替代的口头重复属于常规精剪。若错误讲述或旧板书仍保留在最终视频中，按上述弹窗向用户说明并确认是否更正，再依其选择处理。
3. **未自我纠正的确定计算错误**：用原参数独立计算并追踪后续引用，向用户展示证据与建议并询问是否更正；获确认后在讲述/板书旁标注并同步字幕，必要时按授权补录。新制作 Word 图和公式使用经确认的一致版本。
4. **存在多种合理参数解释**：先查课程原稿、前后期和板书上下文；将不同解释、证据与建议集中询问用户，继续不依赖该答案的工作。不能为了保住后文答案而悄悄改题设。

核对链包括参数和单位 → 公式代入 → 当前一步结果 → 后续迭代/图表 → 总结 → 封面及 Word。修正位置还可能影响之后的速度和位移；另一个独立算例不应继承前例的参数标注。量纲、正负号、坐标方向、角度制/弧度制、单位前缀和 `k` / `k+1` 分别检查。

字幕里改成正确数字而音轨仍明确读错，会产生矛盾。保持原声时加可读的更正说明，并在交付记录中说明；需要补录或替换声音时遵守用户的授权与声音使用要求。

本次第三期的具体质量修订及其授权只见 [episode-03-case.md](episode-03-case.md)。它是历史案例，不能作为以后“发现结果差十倍就把质量乘十”的规则。

## 6. 音频与时间一致性

把最终保留区间按统一时间轴组装音频。根据累计输出帧计算累计样本位置，再取相邻位置的差作为片段长度：`round(frame_end × sample_rate / fps) − round(frame_start × sample_rate / fps)`。不要对 29.97 等非整除帧率使用 `sample_rate // fps` 后逐片段累加。

基础精剪阶段正常讲话保持原速与音高。对确认无解说的书写段，可按画面加速同步处理底噪/书写音；最终将整片按1.25倍导出，使用保持音高的atempo处理，烧录字幕随画面、独立SRT时间码同步缩放。纯重采样会变调，不能用于代替保音高变速。

剪口检查波形跳变；必要时在合适位置加入几毫秒淡入淡出或极短交叉淡化。以听感确认不伤辅音、数字首音或尾音；不能用长淡化掩盖错误切点。交叉淡化带来的时长变化也须进入时间轴。

整片统一人声响度，合理限制峰值，避免每个短句分别归一化造成音量抽动。可将约 −16 LUFS、保留真峰值余量作为网络人声视频的起点，再按发布要求与源质量调整。确认是否需要保持立体声/多音轨；不盲目把独立声道混成单声道。

检查最终 AAC 解码后的峰值、音量突变、底噪和爆音。编码可能产生峰值超调；仅凭编码前 PCM 的峰值不能证明交付音频不削波。也不要把样本峰值测量写成已测真峰值。

## 7. 验收与交付记录

运行 `media_tools.py verify-media` 做媒体结构核对；其支持的字段与全片解码选项见 CLI。把工具检查和内容检查分别记录。任何测试因工具缺失或未执行而跳过，应明确标记，不能写成通过。

### 可以自动核验的内容

- 保留原片 SHA-256 与整理前一致，重复副本操作记录完整。
- 输出的流、尺寸、帧率、编解码器、SAR、时长符合项目；实际输出帧数与编译时间轴一致。
- 音视频时长差在合理的帧/编码边界内；另外检查中段和尾部同步，避免总时长相同但局部漂移。
- 字幕按时序排列、时长为正、无无意重叠和越界；SRT 与实际烧录输入一致。
- 所有配置的更正显示区间重映射完整，且未泄漏到其他算例。
- 最终文件做全片解码，记录退出码及错误输出。只 probe 文件头、抽关键帧或检查大小不构成全片解码。

### 需要直接观看或试听的内容

- 每一处人工删段、加速边界和素材合并接缝：无断字、悬空指代、突兀的板书状态变化。
- 算例条件、公式代入、纠错和下游结果：数值、变量、单位和说明一致。
- 原尺寸最终编码画面：公式清晰，字幕/更正区互不遮挡，封面可读，片尾完整。
- 开头、中段、接缝和结尾的音量与同步；静音书写段仍能理解板书形成过程。

应覆盖全片内容地图和所有剪口，再检查完整成片的播放流程。若任务要求完整逐段试听/观看，按段执行并记录覆盖范围。抽检、短窗 ASR、自动静音分析和整片解码各有边界，报告时准确说明实际完成了哪些，不能写成已完整试听。
