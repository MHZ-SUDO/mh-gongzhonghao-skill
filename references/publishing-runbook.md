# 详细执行步骤

只执行本次范围。下列“点击”均指读取当前快照后，定位当前页面或可见弹窗中的唯一目标，再操作并检查结果。录屏中的位置、类名和URL参数不作为固定选择器。

## 0. 准备本期素材，先查是否已发

恢复超时/继续上次发表时，首先定位原state、原稿身份与原浏览器现场，只读取并恢复，不从下列prepare/init重开一遍。attempted/pending的操作按异常恢复表执行。

1. 阅读本期授权及目录，区分最终讲解MP4、编辑原片、发布操作录屏、封面PNG和配套DOCX。默认不重新编码成片，不动用户源文件。
2. 拟定发布标题：如“第04期_真实主题”。视频标题与文章标题可一致，删除制作文件名后缀；不要擅自改已确认标题。摘要用一两句说明本期内容，不粘贴文件路径或制作日志。
3. 运行prepare、init保存输入哈希；查看视频片头/中段/片尾，确认内容、音画、字幕、32:51这类时长证据与本期相符。DOCX检查正文、全部图片、关键公式、标题和封面，既不要上传原片，也不要把SRT当文章。
4. 健康检查桥接。用find_tab先找公众号；用户说当前页时用active:true，没找到才打开新标签。读当前页面，不擅自移动或关闭用户其他标签。实际会话结束按浏览器技能close_session规则清理，正在验证/发表时不关闭。
5. 如已有登录，先核对公众号；如是登录页，执行第1次扫码。然后到“内容管理→发表记录”和“草稿箱”只读查找本期：标题相同、期次相同、类型、视频时长/正文摘要、封面、时间一起判定。
6. 发现目标已发表：报告其链接并跳过该类型，不创建同一份。目标发表中：只跟踪处理，不再次提交。若该条是用户手动或前会话提交、本地尚无attempt，用adopt认领真实平台身份与证据；不得为了登记pending先commit。原state已有attempt则record后续回执。找到本次未发表草稿：核对身份后续用；已有不相关草稿不覆盖。一个视频、一篇图文同标题是正常组合，不删其中任一条。

## 1. 公众号登录：第1次扫码

1. 入口域名必须为mp.weixin.qq.com；普通文章域名下的读者页面不是管理后台。不要复用录屏地址栏的token。
2. 登录页可能有账号密码、扫码等切换。使用当前扫码登录模式，展示当前有效二维码局部截图，说明“第1处：登录公众号，扫码后请按手机提示确认”。
3. 等待扫码成功并进入后台。用户手机可能有多个账号，入站后再次检查公众号名称为“本期配置中的公众号名称”（若用户本次另指定账号，使用本次值）。账号不符先停止所有写操作，不能在错误账号上试填标题。
4. 首页“你的创作周报”二维码是查看报告，不要当作登录失败后第二个验证。

## 2. 创建公众号视频素材

### 2.1 新建与选择文件

1. 首页“新的创作”区域选“视频”，预期出现“添加视频”页，或本期相同视频草稿编辑页。不要点“文章”编辑器里的“视频”工具冒充同一种流程。
2. 当前上传说明需读取；记录实际大小/时长/格式限制。2026-10-30录屏的长视频32:51可以上传，不能用记忆中的其他平台短视频上限拒绝处理。
3. 找对应视频上传input，上传manifest冻结的单个最终MP4；页面回显文件名、上传进度、时长时与本地核对。等待上传和转码可用，不在进度未完成时刷新。
4. 若已有同一素材且可准确匹配时长/封面/标题，优先选已有素材，不反复上传。文件名相近不等于同一内容。

### 2.2 原创、标题与封面

1. 本系列自有讲解且来源已明确时按既定偏好声明原创，阅读当前原创说明并选择对应确认；第三方素材来源不明确不能自动勾选。不要把法律说明弹窗当作视频发表按钮。
2. 视频素材标题与最终发表标题分开检查。录屏上传页提示标题保存后不可修改，因此必须在保存前完成校对：期次、主题、无文件后缀、无“公众号配套”。按当前字符上限处理，不机械截断关键主题。
3. 封面上传本期PNG，核对缩略图与视频片头/本期主题一致。不同封面比例逐一预览，标题、公式重点、车体别被裁掉；禁止只因出现第一张缩略图就确认。
4. 视频“发表后转为视频号视频”沿用系列已开启偏好，核对当前绑定身份；不要单独跳去视频号后台发布第二份。若当前未绑定、弹出新增授权/协议或身份不明，先读当前说明，不能为减少扫码而绕验证。
5. 标题、封面、进度、原创选项全部正确后保存。录屏使用上传页“保存并发表”进入视频编辑器；如果当前按钮直接导致最终发布，则应先完成发表前检查，不能靠按钮位置猜副作用。仅存草稿模式只选保存。

## 3. 视频编辑器与第2次扫码

1. 核对左侧本期封面卡片、中心标题和播放器、视频时长。播放器出现灰图、加载中或旧期标题时先解决，不触发发表。
2. 检查“合集”并选“本期配置中的合集名称”，回到编辑器后确认显示已关联；不要新增同名合集。录屏05:02合集弹窗并非扫码授权。
3. 原创、留言、平台推荐、视频号同步等设置按本次要求及既定偏好核对。“创作来源”只有适用且事实明确才声明，不能为了凑齐表单乱选。
4. 做页面预览及视频可播放抽查。保存草稿并确认“已保存”；复制编辑器身份供本地记录，URL对外展示时去除token等会话参数。未保存不得清理页面。
5. 打开底栏“发表”，读取当前弹窗：群发通知OFF、定时发表OFF。若平台默认群发ON，明确关闭后读回；不要因“今天还有1次通知次数”就使用这一次额度。只有本次用户明确要求群发时才改变该默认。
6. 按检查表生成video-review.json并通过review，commit成功后点击当前确认弹窗的“发表”。遇“未开启群发通知，继续发表”提示时只确认这是预期非群发模式，点“继续发表”；不返回打开群发。所有确认属于同一提交尝试。
7. 出现“微信验证”：展示本次当前码，说明“第2处：发表《本期标题》视频，公众号为……，群发关闭”。等待用户扫码及手机确认。视频号同步开关不增加一个虚构扫码。
8. “扫码成功”后保持页面，等待“已发表/正在返回首页/发表中”等真实回执。记下本次视频状态和可用ID/链接。后台仍显示发表中时保存pending，后续可以继续独立的图文准备，不重发视频、不声称视频已经完成对外审核。

## 4. 创建配套图文并导入Word

### 4.1 进入空白或已核对的本期文章

1. 从首页“新的创作→文章”进入；若复用本期草稿，核对标题、类型和内容后再进入。不要误进刚刚的视频草稿。
2. 使用原生“文档导入”（可能在工具栏折叠菜单）。读当前格式、大小与覆盖提示。实录支持doc/docx/markdown、≤15M，明确“导入内容将覆盖原有内容”。这些限制以当前页面为准。
3. 空白新稿可直接导入；非空稿只有属于本次待替换内容并已获对应编辑授权才覆盖，否则另建本期文章。导入前保留源文件和已有稿件身份。
4. 使用文件input上传manifest里的单个DOCX。录屏通过资源管理器拖入，不要求助手复刻Windows窗口拖拽；选对文件及结果即可。
5. 等待导入，查看进度和正文。实录约半分钟，不是后面的几分钟排版空白；不要见空白就重复导入。超过正常时间先看任务和原编辑器状态，保留稿件并按异常表处理。

### 4.2 正文、公式与图片

1. 从头滚到底，按本地DOCX的标题/章节/图片索引检查顺序与末尾内容是否完整。图片先等加载；坏图、占位符、缺段、公式变空白都要先修复。
2. 封面正文图、推导图、车辆示意图、数值表与步长比较图分别核对。文本中说“见图”而图不在原位不算导入完成。
3. Word源文件的独立公式为OMML；微信编辑器是否保留结构并不保证。公众号页面以读者看到的公式正确为验收：上下标、分式、积分上下限、希腊字母、单位、小数和正负号逐项检查。不得把XML标签、生LaTeX或乱码当公式。
4. 原生导入若损坏公式，用已验证的原Word公式或同一原始数学内容渲染清晰图片，再通过原生插图放回相应段落，保持上下文。保留源Word的可编辑OMML，不用整页截图代替整篇文章，也不顺手改数学结果。
5. 页面移除不适合网页阅读的页眉页脚、页码及大面积分页空白；保留自然段和逻辑顺序。窄屏重点查卡片/表格横向滚动、公式被截、图片两侧裁切。只做版式修复，不擅自改用户已审定的技术含义。
6. 本地Word中的“配套视频：……”纯文本不等于可播放视频组件。按本次要求插入已发表视频时，用编辑器“视频”工具、已有素材选择对话框准确选择本期视频，核对标题、封面、32:51这类时长及本次身份；不可只选列表第一个同名项。没有实际组件就不能报告“已插入视频”。

### 4.3 一键排版

1. 初步检查正文完整后，保存草稿，读取“已保存”，再点击当前稿件右侧“一键排版”一次。记录原编辑器和新排版任务标签的身份，防止多个同标题标签串稿。
2. 实录11:47打开新about:blank，随后变为公众号articlestruct任务页，约两分钟后才出现结果。空白期间可每15–30秒只读查看新页和原稿；向用户说明在等排版，不要求再扫码，不开第二个相同任务。
3. 排版结果出现后，从头滚到底，读段落、图、公式、表格。确认结果来自本次稿件，再用结果页明确的应用/复制到编辑器按钮；按钮名称以当页为准，不猜“绿色按钮就是应用”。
4. 应用前后比较章节、结尾、图片、关键数值和公式是否完整；打开的编辑器ID/标题仍要对应本期。自动排版可能处理了卡片和表格，也可能引入溢出，必须再次预览。
5. 若任务无结果或正文缺失，保留已保存原稿，回到原编辑器做人工版式整理，或说明排版失败。用户没有要求必须采用某个排版产品，不为等待一键排版无限重试/覆盖。

## 5. 图文元数据与第3次扫码

### 5.1 元数据独立完成

1. 标题栏单独填“第NN期_本期主题”，不能把正文第一行标题当标题栏已填。导入时“请在这里输入标题”仍可能存在；录屏最终去掉“公众号配套”文件名后缀。
2. 作者字段/原创作者按本次要求与本期已确认作者处理；有两个不同作者字段时分别读取，不填写虚构姓名。
3. 设置发布封面，选择本期PNG。正文已有封面图、左侧封面卡片变了，都不必然说明封面表单已保存；确认缩略图、裁剪、选择数量以及红色“必须插入一张图片”之类校验消息的真实状态。必须让有效性错误消失并读回保存结果才继续。
4. 封面与摘要区域的文字框是摘要，不是文章标题，按当前字数限制填写。不把“32分51秒”固定塞进每期摘要，若提时长则取本期实测。
5. 合集关联正确；本系列来源明确时声明文字原创，作者为本期配置的确认值；快捷转载沿用既定已开启偏好。本次要求不同则按本次值。赞赏不开启、留言自动精选公开、平台推荐开启、原文链接不添加陌生链接。
6. 检查创作来源声明是否符合实际。由AI生成的封面、文字等若当前平台要求单独标注，按当前说明和素材真实来源处理，不能为了复刻旧录屏一律选“无需声明”，也不能杜撰全部人工创作。

### 5.2 最终预览、保存与发表

1. 使用公众号原生预览检查首屏、每个章节、公式与图、正文末尾及视频组件。若可在浏览器预览完成，不额外制造一次手机预览扫码；必须手机预览才能判定的问题据实说明，不为凑三次跳过关键检查。
2. 封面标题、列表封面、正文封面都为本期；标题无占位符/文件后缀；配套视频选择无误；无可见错误提示。保存并确认已保存，不用录屏中的3582字作为未来文章的目标字数。
3. 打开底栏“发表”，核对当前为article类型、正确本期标题，群发OFF、定时OFF；截图当前弹窗与终稿证据，保存article-review.json。
4. review及commit通过后，只点一次当前确认弹窗中的“发表”；需要继续非群发时按预期继续。出现图文微信验证码，完整流程可说明“第3处：发表《本期标题》配套图文”；已登录或前阶段已提交时，改说“图文发表验证，本次只需这一处”，不补造前两次扫码。
5. 等用户扫码和手机确认。扫码成功提示明确要求勿关闭页面时保持，直到页面出现实际发表回执。

## 6. 验收与结束

1. 到内容管理→发表记录，分别找本次视频与图文。核对标题、类型、时间、封面、视频时长/文章正文。发表中记pending，已发表记published，失败保存原文；不要把旧期或自动生成的贴图草稿当本次成功。
2. 对已发表内容可打开阅读页或详情只读验证封面、首尾、图文及视频可见。保存可公开分享的文章链接；不可把含后台token的编辑URL当分享链接。
3. 状态脚本分别record；本地记录包含原始输入哈希、检查证据、执行时间与实际回执，无Cookie/登录密钥。QR截图为临时辅助，不打包分享；保存完成页不保留验证会话链接。
4. 报告“视频……；图文……”，附可用链接及本期发布记录；有一项处理中就明确写处理中，不合并成一句“都发布成功”。技能只制作/演练时只报告制作与验证结果。
